# 디자인 원칙 적용 점검

2026-09-20. 기준은 `docs/content/design-principles.mdx`입니다. 이 문서는 이번 점검에서 확인한 사실과 남은 검증 범위를 기록합니다. 라이브러리 전체의 사용성 인증이나 모든 환경의 지원 선언이 아닙니다.

## 방법과 범위

- 기존 반응형·조합 검사 23개를 수정 전에 실행해 기준 상태를 확인했습니다.
- 문서 CSS 없이 실제 컴포넌트로 긴 콘텐츠, 낮은 화면, 중첩 선택, 액션 알림을 구성했습니다. 원본은 `tests/resilience/fixture/principles.tsx`입니다.
- `tests/resilience/principles.spec.ts`는 Dialog SM/MD/LG, Alert Dialog, Drawer, Sidebar LTR/RTL, Toast 라이트/다크, Carousel을 검증합니다.
- `tests/resilience/catalog.spec.ts`는 등록된 모든 실행 예제를 320px 화면의 라이트/다크 테마에서 순회합니다. 이는 초기 렌더와 문서 전체의 가로 넘침 검사이며, 모든 상태·입력 방식·시각적 품질의 검증을 대신하지 않습니다. 테스트 결과에 넘침 상세를 JSON으로 첨부합니다.
- 프로덕션 문서의 기존 UI 검사, 타입·단위 검사, npm 패키지와 CLI 복사본의 실제 Next.js/Vite 소비 환경을 함께 확인합니다.

## 미검증과 후속 범위

아래 항목은 자동 검사 통과로 대체하지 않습니다.

- 실제 iOS/Android 기기의 가상 키보드, 브라우저 주소창·안전 영역 변화, 터치 스크롤과 스와이프의 충돌. 낮은 뷰포트 검사는 이 상황의 일부만 다룹니다.
- VoiceOver/NVDA 등 실제 보조기기로 읽기 순서와 작업 완결성 확인. ARIA/axe 검사만으로 완료를 선언하지 않습니다.
- Chromium 외 지원 브라우저의 동일 시나리오 검증. Dia에서 보고된 깜빡임의 원인은 이번 검사로 확인되지 않았습니다.
- 실제 브라우저 확대, OS 글자 크기, forced-colors, 번역으로 길어진 문구. 좁은 뷰포트는 확대 검사의 대체물이 아닙니다.
- 실제 사용자가 처음 컴포넌트를 찾고 설치·조합·수정하는 과정의 관찰. 사용성 검증은 이번 자동 검사와 별도로 필요합니다.
- 모든 예제의 열린 상태·오류·빈 상태·지연·연속 조작 조합. 전체 예제 순회는 초기 상태만 검사합니다. 컴포넌트별 확인 조건을 늘릴 때 구체적인 사용 흐름을 기록합니다.

## 다음 변경의 검증 원칙

먼저 재현 조건을 만들고 원인과 영향 범위를 구분합니다. 공통 원인이면 공통 구현을 수정하되, 정상인 컴포넌트의 외형을 일괄 변경하지 않습니다. 관련 테스트와 실제 화면을 함께 확인하고, 검증한 범위와 미검증 범위를 별도로 보고합니다.

## 이번 변경의 검증 결과

- `pnpm typecheck`: 통과.
- `pnpm test`: JavaScript 9개, TypeScript 5개 통과.
- `pnpm build`: 레지스트리·Storybook·Next.js 빌드 통과.
- `pnpm test:resilience`: 36개 통과. 이 중 2개는 각 테마에서 등록된 194개 예제 전체를 순회합니다.
- 전체 `pnpm test:ui`: 첫 수정본에서 128개 통과, 짧은 Toast의 불필요한 줄바꿈 2개 실패. 고정 flex-basis를 내용 기준으로 수정했습니다.
- 최종 빌드의 `pnpm exec playwright test toast.spec.ts motion.spec.ts sidebar.spec.ts`: 위 실패 2개를 포함한 관련 28개 통과. 최종 전체 130개를 한 번에 다시 실행했다는 의미는 아닙니다.
- `pnpm package:test`: 최종 소스를 묶은 npm tarball 및 CLI 복사본 모두 TypeScript·Vite·Next.js 빌드와 브라우저 상호작용 통과. 이는 로컬 설치 검증이며 npm 공개 배포는 아닙니다.
- 실제 Chromium 화면에서 수정 전후의 긴 Sidebar·Toast를 비교했습니다. 최종 모바일 액션 Toast는 높이 50px로 한 줄을 유지했습니다.

검사 과정의 두 환경 문제도 제품 결함과 구분했습니다. Vite가 순회 중 의존성을 재최적화하거나 소스 갱신으로 페이지를 다시 로드한 문제는 의존성을 한 번에 로드하고 각 예제를 별도로 재마운트하는 고정 검사 화면으로 해결했습니다. tsx의 로컬 IPC는 샌드박스 밖에서 재실행해 검사를 완료했습니다.
