# 0.3.1 반응형·상태 전환 점검

0.3.0의 문서 렌더링 검사만으로는 실제 조합의 품질을 판단할 수 없었습니다. 문서의 전역 스타일이 없는 독립 React 환경에 200~240px 부모 영역, 긴 이름, 상태 전환을 넣고 실패를 먼저 재현했습니다.

| 문제                                          | 원인                                                       | 변경                                                                                                 |
| --------------------------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 퇴장 중인 Toast의 이전 작업이 계속 노출       | 포인터만 막고 키보드·접근성 탐색에서는 제외하지 않음       | 퇴장·교체 상태에 inert 적용, 모션 완료까지 DOM은 유지                                                |
| CSS를 나중에 불러오면 48px 버튼이 40px로 바뀜 | 공통 기본 스타일과 컴포넌트 스타일의 우선순위가 같음       | 공통 버튼 스타일의 우선순위를 낮추고 Textarea 규칙을 해당 조합에 명시                                |
| 로딩 버튼 폭·포커스·합성한 이름               | Spinner를 내용 옆에 삽입하고 native disabled로 포커스 제거 | 내용 공간을 유지한 중앙 로딩 표시, Base UI의 focusableWhenDisabled, 최종 render 요소의 내용·ref 보존 |
| 페이지 수 감소 후 표시와 상태 불일치          | 표시값만 clamp하고 저장된 선택·콜백은 그대로 유지          | 유효한 페이지를 상태와 콜백에 함께 반영                                                              |
| 좁은 Pagination이 여러 줄로 분리              | flex-wrap에만 의존                                         | 실제 폰트의 너비와 부모 영역을 측정해 직접 페이지 입력으로 전환                                      |
| 공유 Tooltip의 잘못된 설명 연결               | Root의 open 상태를 모든 Trigger에 복제                     | Base UI Trigger의 실제 open 상태 사용, handle별 설명 ID 구독                                         |
| 명시한 Portal 테마가 무시됨                   | 상속한 색상 변수가 직접 지정한 테마를 덮음                 | 테마를 측정하는 원래 위치에 명시한 테마 반영, 방향 전달                                              |
| 표가 부모 밖으로 넘침                         | table 자체만 출력                                          | 의미·ref는 table에 보존하고 기본 스크롤 영역 제공                                                    |
| 긴 탭과 제어된 선택이 화면 밖에 남음          | 스크롤 처리 및 선택 변경 후 노출 처리 없음                 | 내부 스크롤, 선택·크기 변경 관찰, 세로 표시 막대                                                     |
| 긴 이름·OTP 입력이 좁은 영역에 맞지 않음      | nowrap, 고정 높이·너비                                     | 내용 줄바꿈과 최소 높이, OTP 폭 분배                                                                 |
| 가로 ScrollArea 막대가 세로 치수              | orientation별 스타일 누락                                  | 방향별 너비·높이·flex 방향                                                                           |
| 칩보다 큰 삭제 버튼                           | 일반 IconButton 40px 치수 사용                             | 칩 전용 20px 삭제 컨트롤                                                                             |
| 좁은 캐러셀의 일부 카드만 노출                | 카드 280px, 이동 292px 고정                                | 부모 기준 카드 너비, 실제 카드+간격 기준 이동                                                        |
| 숫자 0 장식이 슬롯 밖에 표시                  | JSX의 값 && 요소 조건                                      | React에서 표시하지 않는 값만 제외                                                                    |

## 검증 경로

- `pnpm test:resilience`: StrictMode, 별도 Vite 소비자, 좁은 부모 영역, 외부 handle, render 합성, 키보드 및 리사이즈 회귀 검사.
- `pnpm test:ui`: 기존 문서·Select·Dialog·Toast·모션 회귀 검사.
- `pnpm package:test`: npm tarball과 CLI로 복사한 소스를 각각 Next.js·Vite에서 검증.
- `pnpm test:storybook`: 예제 렌더링과 크기·상태 조합 검사.

이 검증은 설치된 Playwright Chromium에서 실행합니다. Dia의 실제 환경이나 확장 기능을 재현한 결과가 아니며, 모든 브라우저에서 문제가 없다는 근거로 사용하지 않습니다.
