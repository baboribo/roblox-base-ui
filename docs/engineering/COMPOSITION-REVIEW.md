# 조합 화면 검토와 다시 짜기 (3.5단계)

- 날짜: 2026-10-26
- 대상: 2·3단계에서 만든 대표 화면 조합 4개 (`examples/game-discovery.tsx`, `game-detail.tsx`, `chat-history.tsx`, `memory-settings.tsx`)와 Storybook `조합/*` 스토리
- 계기: 사용자 검토에서 "컴포넌트가 깨지고, 디자인 원칙을 못 지키고, 필요 없는 상자를 두른" 조합이라는 지적을 받았습니다.
- 확인 방법: 22개 스토리를 1280px·375px × 라이트·다크로 캡처, 모바일 사이드바·메뉴·대화상자를 직접 열어 확인, 조합 코드와 화면 CSS를 한 줄씩 읽기
- 기준: [디자인 원칙](../content/design-principles.mdx), AGENTS.md("문서 전용 CSS로 라이브러리 결함을 가리지 않는다"), 실제 서비스 수준(구글 플레이 게임 탭·앱 상세, Roblox 게임 페이지, ChatGPT 대화 기록·기억 설정). 홈은 대시보드가 아닙니다.

## 결론

처음 조합의 문제 대부분은 라이브러리가 아니라 **조합 코드**가 만든 것이었습니다.

- 이미 있는 배치 컴포넌트(`Stack`·`Inline`·`Grid`)와 글자 토큰을 쓰지 않고 화면 CSS 약 560줄로 다시 만들었습니다. 구역 제목만 해도 화면마다 크기가 달랐습니다.
- 앱 전체를 테두리 상자에 넣거나, 필터마다 상자를 두르거나, 탭 아래 같은 뜻의 제목을 반복하는 등 필요 없는 상자·래퍼가 많았습니다.
- 점검용 문구("대화 내용은 2번 대화 화면에서 점검합니다.", "선택한 게임: g1")와 동작하지 않는 버튼(다시 시도, 더 보기, 정렬)이 화면에 남았습니다.
- 라이브러리 내부 클래스(`rbx-button`, `rbx-error`)와 data 속성을 빌려 썼고, 알림 영역을 `display:none`으로 숨겼습니다.
- 그래서 1차·2차 점검 문서에도 조합 탓인데 라이브러리 결함으로 적힌 항목이 섞였습니다. 두 문서는 이 검토에 맞춰 바로잡았습니다.

## 다시 짠 원칙

1. 화면 CSS 파일을 두지 않습니다. 네 조합은 이제 다른 컴포넌트 예제와 같은 자급 규칙(`tests/usage.test.mjs`: 라이브러리 컴포넌트·React·lucide만 가져오기, CSS 파일 없음)을 지킵니다.
2. 인라인 `style`은 앱 레이아웃의 몫(화면 최대 폭·바깥 여백, 사이드바 앱 셸 높이), 사용자가 고른 값(배경 흐림·불투명도), 라이브러리에 옵션이 없는 곳에만 쓰고, 그 자리에 점검 문서 번호를 주석으로 남깁니다.
3. 라이브러리 결함은 가리지 않고 보이게 둡니다. 다만 조합을 짜며 새로 찾은 결함 중 작고 명확한 세 가지는 이번에 고쳤습니다(아래 N1~N3).
4. 동작하는 척하는 버튼은 실제로 동작하게 하거나 뺍니다. 상태 알림은 숨긴 live 영역 대신 Toast를 씁니다.

## 3.5단계에서 새로 찾은 라이브러리 문제

| #   | 대상         | 문제                                                                                                                                                                          | 처리                                                        |
| --- | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| N1  | Card         | `layout="horizontal"`에서 본문이 미디어보다 길면 미디어가 `min-height:100%` 때문에 높이 기준으로 너비가 다시 계산되어 열을 넘고 본문 글자를 덮었습니다(긴 한국어 375px 차트). | **고침**: 미디어 너비를 열에 고정(`card.css`)               |
| N2  | Table        | `th`가 브라우저 기본 가운데 정렬이라 머리와 값의 정렬이 어긋났습니다.                                                                                                         | **고침**: `text-align: inherit`(`table.css`)                |
| N3  | Layout       | `Stack`·`Inline`·`Grid` 안의 제목·문단이 브라우저 기본 바깥 여백을 가져 `gap`에 더해졌습니다(처음 조합이 화면 CSS로 margin 0을 덮은 이유).                                    | **고침**: 직계 자식의 위아래 여백 0(`layout.css`, 0 명시도) |
| N4  | Inline       | 줄바꿈을 끄는 옵션이 없어, 긴 제목 옆 버튼(앱 머리 "⋯", 스위치)이 다음 줄로 밀립니다. 조합에서 `style={{ flexWrap: "nowrap" }}`로 우회했습니다.                               | 4단계: `wrap` prop                                          |
| N5  | Button       | `variant="link"`에 `render={<a href />}`를 주면 `role="button"`이 붙어 링크가 버튼으로 읽힙니다. 다크 테마 링크 글자 대비가 axe `color-contrast`에 걸립니다.                  | 4단계. 조합에서는 가짜 "전체 보기" 링크를 뺐습니다          |
| N6  | Button       | 폭 채우기 옵션이 없습니다(`inline-size: fit-content` 고정). 좁은 화면의 주 작업 버튼(플레이, 저장)을 가로로 채울 수 없습니다.                                                 | 4단계                                                       |
| N7  | Typography   | `Heading` 크기가 하나라 앱 머리 제목과 페이지 제목, 구역 제목을 구분할 수 없고 말줄임도 없습니다. 긴 대화 제목이 375px 머리에서 24px로 여러 줄이 됩니다.                      | 4단계, 1차 M7과 함께                                        |
| N8  | Empty, Alert | 기본이 테두리 상자라 구역 안·사이드바 안에 놓으면 상자가 겹겹이 생깁니다. 조합에서는 사이드바 빈 상태·오류를 글과 버튼만으로 표시했습니다.                                    | 4단계, 1차 L1·H5와 함께                                     |
| N9  | List         | `leading`이 세로 가운데 정렬이라 여러 줄 댓글에서 아바타가 이름 줄이 아니라 가운데에 놓입니다.                                                                                | 4단계 (낮음)                                                |

## 검증

- `pnpm test`(자급 규칙에 네 조합 포함), `pnpm typecheck`, Prettier 검사
- 22개 스토리 × 1280/375 × 라이트/다크 axe: 남은 위반은 `Field.Error` 글자 대비(2차 2-H1) 하나입니다. 가로 스크롤 없음
- 키보드: 이름 바꾸기·기억 고치기 대화상자는 입력칸에 첫 포커스, 대화 삭제 뒤 "새 대화", 기억 삭제 뒤 "기억 사용" 스위치로 포커스가 돌아옵니다. 스위치 이름은 "기억 사용"만, 설명은 `aria-describedby`로 연결됩니다.
- 확인하지 못한 것: 실제 스크린 리더, iOS·Android 실기기, 200% 확대, Roblox CDN 글꼴이 불러와진 상태(이 환경은 CDN이 막혀 숫자가 명조로 보임, 1차 H1).
