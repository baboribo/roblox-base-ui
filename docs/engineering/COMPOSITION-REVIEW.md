# 조합 화면 검토와 다시 짜기 (3.5단계)

- 날짜: 2026-10-26
- 대상: 2·3단계에서 만든 대표 화면 조합 4개 (`examples/game-discovery.tsx`, `game-detail.tsx`, `chat-history.tsx`, `memory-settings.tsx`)와 Storybook `조합/*` 스토리
- 계기: 사용자 검토에서 두 번 지적을 받았습니다.
  1. "컴포넌트가 깨지고, 디자인 원칙을 못 지키고, 필요 없는 상자를 두른" 조합이다.
  2. 1차로 다시 짠 화면이 "최신이 아니고 너무 단순하다".
- 확인 방법: 22개 스토리를 1280px·375px × 라이트·다크로 캡처, 모바일 사이드바·메뉴·대화상자를 직접 열어 확인, 조합 코드와 화면 CSS를 한 줄씩 읽기, axe 자동 검사
- 기준: [디자인 원칙](../content/design-principles.mdx), AGENTS.md("문서 전용 CSS로 라이브러리 결함을 가리지 않는다"), 그리고 **2026년 10월 기준 실제 제품 화면**(구글 플레이 게임 상세, ChatGPT 홈·개인 맞춤 설정, Gemini 홈, Claude 홈·설정 메모리). 홈은 대시보드가 아닙니다.

## 결론

두 번의 검토에서 원인이 서로 달랐습니다.

- **1차(조합 탓):** 처음 조합은 이미 있는 배치 컴포넌트(`Stack`·`Inline`·`Grid`)와 글자 토큰을 쓰지 않고 화면 CSS 약 560줄로 다시 만들었습니다. 앱 전체를 테두리 상자에 넣고, 필터마다 상자를 두르고, 탭 아래 같은 뜻의 제목을 반복했습니다. 점검용 문구("선택한 게임: g1")와 동작하지 않는 버튼이 화면에 남았고, 라이브러리 내부 클래스(`rbx-button`)를 빌려 쓰고 알림 영역을 `display:none`으로 숨겼습니다. 그래서 1차·2차 점검 문서에도 조합 탓인데 라이브러리 결함으로 적힌 항목이 섞였습니다.
- **2차(규칙 탓):** 1차 수정에서 "화면 CSS 파일을 아예 두지 않는다"는 규칙을 스스로 세웠더니, 라이브러리에 아직 없는 구조(히어로, 선반, 설정 묶음 상자, 평가 막대, 리뷰 답변)를 만들 수단이 사라져 화면이 실제 제품보다 훨씬 성겼습니다. 상세 화면이 제목 + 표 + 문단 몇 개로 끝나는 식이었습니다. **빈약함은 라이브러리 한계가 아니라 이 규칙이 만든 결과였습니다.**

## 다시 짠 원칙 (2차에서 바뀜)

1. **화면 배치 CSS는 화면마다 한 개씩 둡니다**(`examples/<화면>.css`). 대신 아래 조건을 `tests/usage.test.mjs`가 검사합니다.
   - 라이브러리 클래스(`.rbx-*`)를 선택자로 쓰지 않습니다. 라이브러리 결함을 덮지 않기 위해서입니다.
   - 색·글자·간격·모서리·포커스 링은 **토큰만** 씁니다. 색상 값(`#…`, `rgb()`, `hsl()`)을 직접 쓰지 않습니다.
   - `!important`를 쓰지 않습니다.
   - 가져오기는 React·lucide·라이브러리 컴포넌트와 자기 화면 CSS 한 개까지입니다.
2. 라이브러리에 **있는 것은 반드시 라이브러리로** 만듭니다(Button, IconButton, Toggle, Badge, Dialog, AlertDialog, Menu, Field, Form, Select, Slider, Switch, Input, Textarea, Avatar, Skeleton, Alert, Toast, Sidebar, Collapsible, RadioGroup, Stack·Inline). 화면 CSS는 **배치와 화면 고유 구조**만 담당합니다.
3. 라이브러리 결함은 가리지 않고 보이게 둡니다. 조합을 짜며 새로 찾은 결함 중 작고 명확한 것만 그때 고치고(N1~N3), 나머지는 아래 표에 적어 4단계로 넘깁니다.
4. 동작하는 척하는 버튼은 실제로 동작하게 하거나 뺍니다. 상태 알림은 숨긴 live 영역 대신 Toast를 씁니다.
5. 화면의 완성도는 **실제 제품과 같은 정보량**으로 판단합니다. 섹션 하나가 제목 + 문단 하나로 끝나면, 그 화면은 아직 덜 된 것입니다.

## 화면별 구성 (2차)

| 화면      | 참고한 실제 화면                                   | 지금 담고 있는 것                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 게임 탐색 | 구글 플레이 게임 탭, Roblox 홈                     | 페이지 제목 + 장르 칩 줄 → 큰 히어로 배너(그림 위 제목·설명·바로 플레이·점 네비) → 에디터 추천 가로 선반(16:9 그림 + 아이콘 + 제작자) → 인기 게임 격자(정사각 썸네일, 신작·이벤트 배지, 추천 %·동시 접속) → 실시간 차트(순위·순위 변동 화살표, 종류 칩) → 장르 바로가기                                                                                                                                                                                                                                                                          |
| 게임 상세 | 구글 플레이 앱 상세(블루 아카이브·트릭컬 리바이브) | 대표 이미지가 깔린 어두운 히어로(제목·제작자 링크·구매 안내) → 아이콘 + 숫자 요약(추천 %·플레이 중·누적 방문·이용 등급) → 플레이·공유·위시리스트·트레일러 → 스크린샷 가로 줄(좌우 화살표, 눌러서 크게 보기) → "게임 소개 →"(4줄 접기, 업데이트 날짜, 태그 칩) → 이벤트 및 혜택 카드 → 평가 및 리뷰(기기 칩, 큰 추천 %, 추천/비추천/최근 30일 막대, 내 평가, 리뷰: 아바타·추천 여부·플레이 시간·날짜·본문·"이 리뷰가 유용했나요?"·제작자 답변) → 새로운 기능 → 신고. 오른쪽 열에 이용 등급 카드, 게임 지원(접기), 비슷한 게임, 제작자의 다른 게임 |
| 대화 기록 | ChatGPT·Gemini·Claude 홈                           | 사이드바(서비스 이름·접기, 새 대화, 검색, 라이브러리·프로젝트, 고정됨, 날짜 묶음 + "모두 보기", 아래 프로필 메뉴) + 본문(머리: 제목·공유·⋯ 메뉴). 대화를 고르면 말풍선 대화 보기(답변 아래 복사·다시·좋아요)와 아래 고정 입력창, 새 대화면 가운데 인사 + 입력창(+·답변 방식 메뉴·음성·보내기) + 제안 칩 + 최근 만든 것 카드                                                                                                                                                                                                                      |
| 기억·설정 | Claude 설정 메모리, ChatGPT 개인 맞춤 설정         | 왼쪽 설정 목록(검색, 환경설정/사용자 지정 묶음) + 오른쪽 묶음 상자. 기억: 스위치 4줄(기억 사용·지난 대화 검색·민감한 주제·내보내기)과 모두 지우기, 저장된 기억 표(주제·요약·업데이트 날짜·고치기·지우기)와 아래 기억 추가 입력줄. 배경: 미리보기(말풍선 포함)·기본 배경 고르기·내 사진 올리기·글자 뒤 어둡게·흐림/불투명도. 나에 대해: 이름·하는 일·말투·소개 폼, 성격 다듬기 드롭다운 줄, 데이터 관리 이동 줄(>)                                                                                                                                |

모든 화면에서 빈 상태·로딩·오류, 1280/375, 라이트/다크, 긴 한국어를 함께 확인합니다.

## 3.5단계에서 새로 찾은 라이브러리 문제

| #   | 대상         | 문제                                                                                                                                                                            | 처리                                                        |
| --- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| N1  | Card         | `layout="horizontal"`에서 본문이 미디어보다 길면 미디어가 `min-height:100%` 때문에 높이 기준으로 너비가 다시 계산되어 열을 넘고 본문 글자를 덮었습니다.                         | **고침**: 미디어 너비를 열에 고정(`card.css`)               |
| N2  | Table        | `th`가 브라우저 기본 가운데 정렬이라 머리와 값의 정렬이 어긋났습니다.                                                                                                           | **고침**: `text-align: inherit`(`table.css`)                |
| N3  | Layout       | `Stack`·`Inline`·`Grid` 안의 제목·문단이 브라우저 기본 바깥 여백을 가져 `gap`에 더해졌습니다.                                                                                   | **고침**: 직계 자식의 위아래 여백 0(`layout.css`, 0 명시도) |
| N4  | Inline       | 줄바꿈을 끄는 옵션이 없어, 긴 제목 옆 버튼이 다음 줄로 밀립니다.                                                                                                                | 4단계: `wrap` prop                                          |
| N5  | Button       | `variant="link"`에 `render={<a href />}`를 주면 `role="button"`이 붙어 링크가 버튼으로 읽힙니다. 다크 테마 링크 글자 대비도 axe에 걸립니다.                                     | 4단계. 조합에서는 링크를 `a`로 직접 만들었습니다            |
| N6  | Button       | 폭 채우기 옵션이 없습니다(`inline-size: fit-content` 고정). 좁은 화면의 주 작업 버튼(플레이)을 가로로 채울 수 없어 화면 CSS로 최소 너비를 줬습니다.                             | 4단계                                                       |
| N7  | Typography   | `Heading`은 h2 한 크기뿐이라 페이지 제목(h1)·구역 제목을 구분할 수 없고 말줄임도 없습니다. 네 화면 모두 제목을 화면 CSS에서 만들었습니다.                                       | 4단계, 1차 M7과 함께                                        |
| N8  | Empty, Alert | 기본이 테두리 상자라 구역 안·사이드바 안에 놓으면 상자가 겹겹이 생깁니다. 조합에서는 빈 상태를 글과 버튼으로 표시했습니다.                                                      | 4단계, 1차 L1·H5와 함께                                     |
| N9  | List         | `leading`이 세로 가운데 정렬이고 본문 자리가 `Title`·`Description`뿐이라 리뷰·기억처럼 여러 줄짜리 항목에 맞지 않습니다. 두 화면 모두 List 대신 화면 구조를 만들었습니다.       | 4단계                                                       |
| N10 | Tabs         | 세로 탭(`orientation="vertical"`)도 글자가 가운데로 모여 설정 목록처럼 보이지 않고, 묶음 제목을 사이에 넣으면 가로로 흩어집니다. 기억·설정은 `NavigationItem`으로 만들었습니다. | 4단계                                                       |
| N11 | Button       | `variant="alert"` 버튼의 글자 대비가 라이트·다크 모두 axe `color-contrast`에 걸립니다(라이브러리 자체 스토리 `입력/Button`에서도 같음).                                         | 4단계                                                       |

## 검증

- `pnpm test`(화면 CSS 규칙 검사 포함), `pnpm typecheck`, Prettier 검사
- 조합 스토리 × 1280/375 × 라이트/다크 axe: 남은 위반은 라이브러리 쪽 두 가지(`Button variant="alert"` 글자 대비 N11, `Field.Error` 글자 대비 2-H1)뿐입니다. 가로 스크롤 없음
- 키보드: 이름 바꾸기·기억 고치기 대화상자는 입력칸에 첫 포커스, 대화 삭제 뒤 "새 대화", 기억 삭제 뒤 "기억 사용" 스위치로 포커스가 돌아옵니다. 가로 스크롤 영역(숫자 요약)은 탭으로 잡힙니다.
- 확인하지 못한 것: 실제 스크린 리더, iOS·Android 실기기, 200% 확대, Roblox CDN 글꼴이 불러와진 상태(이 환경은 CDN이 막혀 숫자가 명조로 보임, 1차 H1).
